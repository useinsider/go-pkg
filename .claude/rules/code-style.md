# Go code style — go-pkg

Scoped to this shared library. Idioms here are chosen so every `ins*` package
stays interchangeable for callers.

## Formatting

- `gofmt -s` (simplify) is the only allowed formatter. No other opinions.
- `goimports` grouping: stdlib, then third-party, then `github.com/useinsider/...`.
- Line length: no hard limit; break when a line hurts readability, not before.

## Linting

- `.golangci.yaml` at the repo root is the single source of truth for style
  beyond `gofmt`: it is the shared DataForce set (wsl, whitespace, revive,
  errorlint, errcheck, gosec, staticcheck, govet, bodyclose, contextcheck,
  forcetypeassert, nestif, nilerr, nilnil, thelper, unparam, unused, ...)
  in golangci-lint v2 format. Run it per module with
  `golangci-lint run --config <repo-root>/.golangci.yaml ./...`; CI runs the
  same as the `golangci-lint` check on push and PR.
- Anything this file says that the config contradicts is wrong here — fix
  the file, not the config.
- Suppressions go in `linters.exclusions.rules` with a `path:`/`text:`
  narrowing and a comment; never inline `//nolint`, never a `disabled:` list
  under `settings.revive.rules` (that empties revive's rule set in v2).
- Exported identifiers are exempt from revive's `var-naming` (see
  api-stability.md); unexported ones are not.
- `golangci-lint run --fix` handles wsl/whitespace/usestdlibvars/errorlint
  mechanically, but review its diff: it once rewrote a `net.Error` type
  assertion in `inskinesis/customretryer.go` and dropped the `Timeout()`
  check, and it does not add the `errors` import it needs.

## Naming

- Package names are always `ins<thing>` — e.g. `insredis`, `insgorm`. Never
  stutter in exported names (`insredis.Client`, not `insredis.RedisClient`).
- Constructors: `New(cfg Config) Interface`. Never return the concrete struct.
- Config struct is always `Config` (one per package). Optional overrides go
  through additional constructors (`NewWithFoo`) or functional options, not
  new exported fields on existing callers' zero-values.
- Errors are exported as `Err<Reason>` sentinels (e.g. `ErrNotFound`) when
  callers should compare with `errors.Is`; otherwise wrap with
  `fmt.Errorf("...: %w", err)`.

## Structure

- One interface per package, named `Interface`, for new packages. Callers
  depend on it, not on the concrete type. Existing packages predate this and
  keep their names (`insredis.RedisInterface`, `insrequester.Requester`,
  `inskinesis.StreamInterface`, `inssqs/sqs.API`); only `inslogger` and
  `inssqs` use `Interface` today. Renaming would be a breaking change.
- Unexported struct (`client`, `queue`, `stream`, ...) implements the
  interface.
- Mock lives in `<pkg>_mock.go` alongside the real file, generated with
  `mockgen`. Commit the generated file — CI does not regenerate. Keep the
  `// Code generated by MockGen. DO NOT EDIT.` header: the linter skips
  generated files only when that header is present, and most committed
  mocks here lack it, so they are linted like hand-written code.

## Things to avoid

- `panic` in library code. Return errors; the caller decides whether to panic.
  Existing panics (`inssqs.NewSQS` on missing region/queue or AWS config
  failure, `insssm` on SSM failures, `inssentry.Fatal` by design) are
  observable behaviour and stay until a major bump — don't add new ones.
- `fmt.Print*`/`println` (forbidigo). Log through the package's logger; where
  stdout/stderr output is the documented behaviour (`inskinesis` verbose
  mode, `FakeStream`) write to an explicit `os.Stdout`/`os.Stderr`.
- `init()` functions with side effects (registering metrics, dialing network,
  reading env). Make it explicit through `New`.
- Global mutable state. Every package is used by many services concurrently.
- Direct `os.Getenv` reads. Config comes through `Config`, caller loads env.
